# SRTube

Telegram-бот: ссылка на видео YouTube → MP3 320 кбит/с с названием трека, исполнителем и встроенной обложкой. Отдельная кнопка открывает slowed + reverb с голосовым предпрослушиванием из середины трека.

Рабочий процесс теперь разделён: **dev** запускается через `make dev` с `.env.dev`, **production main** — в изолированных контейнерах. Обновление применяется только после успешного CI. См. [разработку и откат](docs/development-and-releases.md) и [разбор безопасности](docs/security.md). Старые команды с `.env` ниже оставлены для совместимости и разового обслуживания; не используй один Telegram-токен в двух одновременно запущенных окружениях.

## Возможности

- Ссылки `youtube.com/watch`, `youtu.be`, YouTube Music, Shorts и записи эфиров. Плейлисты игнорируются: обрабатывается одно видео.
- Лучший доступный аудиопоток через yt-dlp; одна конвертация в MP3 320 кбит/с через LAME. В готовом файле — ID3v2.3: название, исполнитель, источник и JPEG-обложка. Обложка видна и в плеере Telegram.
- Slowed от 0 до 50% с понижением тона: 20% означает скорость 80%, длительность увеличивается в 1,25 раза.
- Reverb от 0 до 100%: доля обработанного сигнала в смеси. Используется свёрточная стереореверберация с ранними отражениями и затухающим хвостом, а также лимитер против клиппинга.
- Изменение параметров кнопками с шагом 5% либо точный ввод двух целых процентов, например `17 35`.
- Голосовое превью OGG/Opus длительностью до 20 секунд: середина исходного трека, с тем же обработчиком и настройками, что у полной версии. Перед фрагментом прогревается реверберация; на краях превью — короткое затухание.
- Полная обработанная версия также приходит MP3 320 кбит/с с тегами и обложкой. Обработка идёт из исходного аудиопотока, без повторного пережатия ранее созданного MP3.
- Очередь с ограничением нагрузки; одна задача на пользователя. SQLite хранит готовые треки, кнопки работают после перезапуска, пока файлы есть в кэше.
- Автоочистка кэша по времени и объёму; временные превью и обработанные копии удаляются после отправки. Активные и ожидающие треки защищены от очистки.
- Закрытый доступ: админка `/admin` в Telegram с добавлением, удалением и списком разрешённых ID. Пустой список оставляет доступ только администраторам.
- Импорт сессии YouTube без пароля в коде, диагностика для владельца, последовательные обращения к YouTube с интервалом и временная пауза после ограничений.
- Повторная отправка той же ссылки пользователем использует его готовый MP3 из кэша, без нового запроса к YouTube.

320 кбит/с — качество кодирования MP3. Оно не восстанавливает детали, уже потерянные в аудио YouTube. Название и исполнитель сначала берутся из музыкальных метаданных YouTube; если их нет — из названия вида `Артист — Трек`, затем из названия ролика и имени канала. Это эвристика, не распознавание музыки. Обложка — изображение ролика в квадратном оформлении; если оно недоступно, используется обложка SRTube.

## Быстрый запуск на macOS / Linux

Нужны Python 3.12+, [uv](https://docs.astral.sh/uv/getting-started/installation/), FFmpeg (вместе с ffprobe, libmp3lame и libopus) и Node.js 22+ либо Deno 2.3+.

Для macOS:

```sh
brew install uv ffmpeg node
cd /Users/subnetmasked/Projects/SRTube
uv python install 3.12
uv sync --frozen
test -f .env || cp .env.example .env
chmod 600 .env
```

1. Создай бота командой `/newbot` у [@BotFather](https://t.me/BotFather).
2. Открой `.env` и заполни `BOT_TOKEN=токен_бота`.
3. Заполни `ADMIN_USER_IDS`: числовой Telegram ID владельца. Пустой список пользователей не открывает бота всем. `ALLOWED_USER_IDS` можно использовать для первоначального заполнения списка; дальше управление идёт через `/admin`.
4. Проверь зависимости и запусти:

```sh
uv run srtube --check
uv run srtube
```

Также работает `uv run python -m srtube`. Используется long polling, поэтому домен, публичный порт и вебхук не нужны. Одновременно должен работать один экземпляр бота с данным токеном. Локальная блокировка предотвращает два процесса с одной папкой `DATA_DIR`.

`--check` проверяет локальные зависимости и формат токена; сетевую доступность YouTube и авторизацию Telegram он не проверяет. Перед отправкой первой ссылки открой личный чат с ботом и нажми «Старт».

## Как пользоваться

1. Пришли одну ссылку на YouTube. Бот скачает аудио, подготовит MP3 и отправит его как музыкальный трек.
2. Нажми «Сделать slowed + reverb» под MP3.
3. Выбери проценты кнопками или нажми «Ввести точные проценты» и отправь, например, `17 35`.
4. Нажми «Голосовое превью», послушай фрагмент и при необходимости измени параметры.
5. Нажми «Получить полный MP3» в панели или под нужным превью. Кнопка под превью сохраняет именно его настройки.

Команды: `/start`, `/help`, `/last` (повторить последний готовый трек), `/cancel` (отменить ввод процентов). `/cancel` отменяет только текстовый ввод; запущенная обработка продолжается. После перезапуска незавершённый ввод процентов нужно начать снова; настройки в кнопках сохраняются.

## Админка и доступ пользователей

Владелец открывает `/admin` в личном чате с ботом:

- «Добавить ID» — введи один или несколько положительных Telegram user ID через пробел, запятую или новую строку.
- «Удалить ID» — отозвать доступ; новые сообщения и старые кнопки перестают работать сразу. Отзыв проверяется и перед обработкой ожидающей задачи, и перед отправкой результата.
- «Разрешённые пользователи» — список с постраничным просмотром.
- «Подключение YouTube» — состояние cookies, настройки provider / прокси, последняя причина отказа и кнопка сетевой проверки.

Команда `/id` доступна даже тем, кого ещё нет в списке: она показывает только собственный ID. Пользователь передаёт его владельцу для добавления. Доступ к `/admin` проверяется по числовому ID из `ADMIN_USER_IDS`, включая нажатия кнопок; один username не даёт прав администратора.

Список разрешённых пользователей хранится в `data/srtube.sqlite3` и переживает перезапуск. `ALLOWED_USER_IDS` импортируется ровно один раз при первом запуске с админкой; удалённые через админку пользователи не восстанавливаются из `.env`. Администраторы имеют доступ отдельно, их список меняется в `.env` с перезапуском.

## Подключить Google-сессию для YouTube

Пошаговая [инструкция по экспорту и подключению cookies](docs/youtube-session.md) описывает вход под запасным аккаунтом, импорт и проверку проблемного ролика. Пароль Google вводится только в браузере.

```sh
uv run srtube --import-cookies ~/Downloads/youtube.cookies.txt
uv run srtube --check-youtube 'https://www.youtube.com/watch?v=GRdLzMBhpss'
```

Cookies сохраняются в `data/auth/youtube.cookies.txt` с правами `600`; новые загрузки подхватывают изменения без перезапуска. Для каждого процесса yt-dlp создаётся отдельная временная копия, чтобы он не менял исходный файл. Само наличие cookies и PO Token provider не гарантирует снятия ограничений YouTube; сессия и исходящий IP также должны приниматься сервисом.

## Настройки `.env`

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | пусто | Токен от BotFather |
| `ADMIN_USER_IDS` | пусто | ID владельцев админки через запятую; обязателен для запуска |
| `ALLOWED_USER_IDS` | пусто | Разрешённые ID для однократного начального импорта; пусто — только администраторы |
| `DATA_DIR` | `./data` | SQLite, оригинальные потоки, MP3 и обложки |
| `MAX_DURATION_SECONDS` | `1200` | Максимальная длительность исходного видео |
| `MAX_UPLOAD_BYTES` | `49000000` | Запас относительно ограничения Telegram в 50 МБ |
| `MAX_DOWNLOAD_BYTES` | `200000000` | Ограничение скачиваемого файла для yt-dlp |
| `MAX_WORKERS` | `2` | Число параллельных задач скачивания / обработки / отправки |
| `MAX_QUEUE` | `8` | Число дополнительных ожидающих задач |
| `PREVIEW_SECONDS` | `20` | Длина голосового превью, 5–30 секунд |
| `CACHE_HOURS` | `24` | Срок хранения после последнего обращения |
| `MAX_CACHE_BYTES` | `5000000000` | Объём кэша; самые давно использованные треки удаляются первыми |
| `DOWNLOAD_TIMEOUT_SECONDS` | `300` | Таймаут каждого этапа yt-dlp |
| `RENDER_TIMEOUT_SECONDS` | `300` | Таймаут FFmpeg |
| `YOUTUBE_COOKIES_FILE` | пусто | Внешний Netscape cookies.txt; иначе используется импорт из `DATA_DIR/auth/youtube.cookies.txt` |
| `YOUTUBE_PROXY` | пусто | Прокси для yt-dlp |
| `YOUTUBE_POT_PROVIDER_URL` | пусто | URL внутреннего сервиса PO Token provider |
| `YOUTUBE_PLAYER_CLIENTS` | `default` | Клиенты yt-dlp; с provider по умолчанию выбираются `mweb,tv,web_safari` |
| `YOUTUBE_MIN_INTERVAL_SECONDS` | `5` | Минимальный интервал между началами обращений к YouTube; они выполняются последовательно |
| `YOUTUBE_COOLDOWN_SECONDS` | `60` | Пауза после отказа входа / HTTP 429 / 403 |

По публичному [Telegram Bot API](https://core.telegram.org/bots/api#sendaudio) аудиофайлы ограничены 50 МБ. Длинный трек после замедления может не поместиться: бот сообщит об этом, сохранив возможность короткого превью. Битрейт автоматически не снижается. Периодическая очистка выполняется каждые 5 минут; активные задачи могут временно увеличить объём кэша сверх установленного значения.

## Docker

Образ включает Python, FFmpeg, Node.js и зависимости из `uv.lock`. Контейнер работает от непривилегированного пользователя; данные лежат в именованном томе.

```sh
test -f .env || cp .env.example .env
# Заполни BOT_TOKEN и ADMIN_USER_IDS в .env
docker compose up -d --build
docker compose logs -f bot
```

Остановка без удаления кэша:

```sh
docker compose down
```

Cookies можно импортировать прямо в постоянный том контейнера:

```sh
docker compose exec -T bot python -m srtube --import-cookies - < ~/Downloads/youtube.cookies.txt
```

Либо добавь bind mount файла только для чтения и установи `YOUTUBE_COOKIES_FILE=/app/cookies.txt`. Cookies и `.env` исключены из сборки образа и Git.

Опциональное дополнение с PO Token provider для сервера:

```sh
docker compose -f compose.yaml -f compose.youtube.yaml up -d --build
```

Provider доступен только боту во внутренней сети, без опубликованного порта. Версия образа `2.0.2` соответствует установленному Python-плагину из `uv.lock`; при обновлении плагина обновляй и образ. Сохраняй том `srtube_data`: в нём база разрешённых ID, сессия и кэш. Развёртывание на арендованном сервере выполняется отдельно.

## Если YouTube не скачивается

YouTube иногда требует вход, ограничивает IP сервера или доступ к конкретному ролику. Бот выводит понятную ошибку; приватные видео, текущие эфиры и будущие премьеры не обрабатываются.

- Обнови yt-dlp вместе с EJS: `uv lock --upgrade-package yt-dlp --upgrade-package yt-dlp-ejs`, затем `uv sync --frozen`. Для Docker после этого пересобери образ.
- Убедись, что работает поддерживаемый JS runtime. [Официальная инструкция yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/EJS) описывает Deno / Node и пакет `yt-dlp-ejs`, который уже включён в зависимости этого проекта.
- Если требуется авторизация, импортируй сессию по [инструкции](docs/youtube-session.md). Для сетевых ограничений предусмотрен `YOUTUBE_PROXY`; для требующих PO Token форматов — `compose.youtube.yaml`.
- Если локальный кэш истёк, пришли ссылку снова.

## Проверки и устройство проекта

```sh
uv run pytest -q
uv run ruff check src tests
uv run ruff format --check src tests
```

Тесты не требуют Telegram-токена и сети. Они проверяют реальную обработку FFmpeg, битрейт, Unicode-теги и встроенную обложку, изменение длительности и частоты сигнала, середину голосового превью, хвост реверберации, лимиты, владение треками, очередь и сценарий Telegram через подменённую сетевую сессию. Дополнительные проверки покрывают закрытый доступ, права на админку, добавление и отзыв ID, миграцию списка, импорт cookies и временную паузу после отказов YouTube.

- `src/srtube/bot.py`, `keyboards.py` — русский интерфейс, команды и обработчики.
- `admin.py`, `access.py` — админка и проверка доступа.
- `youtube.py` — проверка / импорт cookies и диагностика отказов.
- `media.py`, `artwork.py` — yt-dlp, звук, ID3 и обложки.
- `storage.py`, `jobs.py` — SQLite, кэш и очередь.
- `process.py` — асинхронные процессы с таймаутом и остановкой дочерних процессов.
- `config.py`, `__main__.py` — настройки, проверка окружения и запуск.
